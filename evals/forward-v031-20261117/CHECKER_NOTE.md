# 引用検査の誤警報

固定済みの8つの (d) 出力に、候補版と同じ `verify_quotes.py` を `--draft` 付きで適用した。生の結果は7出力が exit 0、case03 の2回目（p16）が exit 1。検査器やモデル出力を直してから再実行する操作はしていない。

検出対象は Evidence セル内の対応引用符付き範囲。423引用中421引用が指定ブロックで FOUND、2引用が UNKNOWN ID。長さ違反、引用なし行、構文問題は各0。本文や Evidence 外の引用を含む「すべての引用」の検証ではない。

p16 の行4は L35 を示した後、地の文で「通常別名のv3と全件比較して」と説明し、その後に2引用を置いている。検査器のIDパターンが版名 `v3` を追加の記録IDと解釈し、そのIDがないため2引用を不合格にした。

実際の2引用は両方とも L35 内に一致する。

- `missing=[] / extra=[] / mismatched=[]`
- `取得から比較終了まで変更ストリームの追加はない。`

L35 自体にも通常別名の参照する v3 と全件比較したことが記録されている。したがって、この2件は引用の捏造や別ブロックへの誤帰属の証拠にはならない。`checker-false-positive.json` は引用の一致、原出力ハッシュの不変、検査器を変更していないことを記録する。判定は「機械通過7/8、残る1出力の2引用は手動で L35 一致を確認」。機械通過8/8へ書き換えない。

固定ヘッダーと必須4セクションは8/8出力に存在した。これは形式の確認であり、台帳の意味、全主張の網羅、修正報告の正確さ、下流エージェントの安全性の確認ではない。

この実験では検査器の修正は行わない。版名と明示的な引用IDの曖昧さは、別の修正・回帰確認が必要な既知の制約として残す。
