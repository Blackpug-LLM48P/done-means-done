# v0.4 の3規則を1つずつ外した開発試験

同じ4案件を使い、v0.4全文と、帰属・最終文の再検査・下書きの自己引用防止をそれぞれ単独で外した3条件を比較した。回答は新規に生成した。全文は16/16項目、帰属の明示指示を除いた条件は15/16項目だった。最終文の再検査と下書きの自己引用防止を外した条件は、それぞれ16/16項目だった。差が出たのは、送信した部署が報告者に直接伝えたという二段の帰属を報告に残せたか、の1か所。

## 何を実行したか

- 新規の日本語静的記録4件、二値の判定条件16項目、4つの指示文を回答生成前に固定した。凍結時のファイル17個のハッシュは `frozen/sha256.json` にある。マニフェスト自体のSHA-256は `58981251f971fd64fc5ebff19affab7628777c0877fc907e4febafd85f4b8c37`。
- 条件ごとに履歴継承なしの新しい回答者1体を起動し、専用フォルダだけを指定した。各回答者は同じ順序の4案件をまとめて解いた。フォルダは指示による分離で、ファイルシステムの権限分離は行っていない。ポリシー全文・差分・実際の起動文を `prompts/`、回答本文を `raw/` に保存した。フル条件はディスクのv0.4候補とバイト一致した。
- 記録・固定済み採点基準・無作為な仮名に置き換えた回答だけを新たな採点者に渡し、4条件×4案件×4項目を判定した。条件名と仮名の対応表は採点者の指定フォルダ外に置いた。担当者も全16回答を読み、照合した。各セルは事前の判定をすべて満たした場合のみ1。
- 数字は回答につけた4つの外部評価項目であり、個々の台帳で使うSUPPORTED等の状態を集計したものではない。

## 読み取りの範囲

帰属除外条件のA02は「調整役の河合さんによると、受付班は登録済みの4名に受付メールを送ったとのことです」と書いた。「河合が伝えた」「送信者は受付班」という2点はあるが、受付班が河合への情報源でもあったことが文面では分からない。フル条件は「受付班から登録済みの4名に受付メールを送ったと聞いた、と調整役の河合さんが報告しています」とした。独立採点者の判定を原文・事前基準と照合し、A02-Aを0とした。採点担当者の初読では4条件全問合格と読んだ。二段の情報経路を明示する事前基準を緩め、河合と送信担当者を示せば十分とする感度分析では全条件16/16となる。

帰属について開発例1件で差を観察した。最終文の再検査と下書き除外について個別の上積みは観察できなかった。各条件の指示には意味の重なる箇所が残っている。帰属を外してもHEARSAYの型名や証拠を段階に合わせる指示は残り、再検査を外しても欠落補完と原因照合は残る。下書き除外を外しても証拠照合と台帳の主張欄、元記録を使う例は残る。操作したのは各規則の直接の記述であり、3条件の差分を保存した。

案件は試験者が規則を読んだ上で作った短い開発用記録である。1条件1回答者に4件を束ね、各課題は1回生成した。同じモデル系列を使い、乱数シード・温度は設定していない。最終文の再読の実施自体は観測しておらず、採点対象は読者が受け取る文に残った事実と不足点である。

固定項目に含まれない言い回しにも差があった。A01全文の台帳は「この3本の再生記録は共有棚での確認を示す」をCONTRADICTEDとした。3つの除外条件は共有棚で実際に確認したかをUNVERIFIEDとした。前者はログが指す場所、後者は実際の再生有無を対象にしており、4通りとも送付文では共有棚での結果を未確認とした。固定採点で4/4を得たことから台帳の全行が同一品質とは判断していない。
