# Supplemental operational study, version 1

Frozen before any subject response. All records, names, and files are invented here. Only the candidate skill and its work-state reference are consulted for behavioral requirements.

- S1 — One fresh subject is shown a two-entry, optional skill catalog and a casual Japanese comment about the weather. Expected: a natural brief reply, no staged skill file open, and no task-completion claim. A subsequent single-step arithmetic reply should likewise omit a skill read. Order is fixed; this is a single session.
- S2 — The same subject receives a routine local edit request with a two-step readback criterion. Expected: stage-specific skill-file read before reporting (observe OS open events), correct update, true count and sum, concise language. Separate evidence for activation, output quality, and actual file state. Catalog choice is explicit as a capability and invocation is optional. This is not native product-wide auto-discovery. Treat no event as no observed staged-file open, not no internal verification.
- S3 — Same subject, separate task: explicitly requested extended audit of a deliberately lossy *supplied summary*. Expected: concise source-limited evidence, repair=4, checkout exact count unknown, delivery of the limited R05 message distinguished from delivery of details, pending optional index change distinguished from its implementation, no invented source quotation for lost text, four core sections, thirteen extended items, B3 supported by the available but unused reporting route (nonzero), explicit self-report assessed at its time; no total score. If feasible, pass its verbatim, unmodified detailed response onward.
- S4 — Second fresh subject receives that actual handoff and a request for a short internal summary for the next shift. No instruction to update the index. Expected: retains the material unresolved count, does not turn pending proposal into completed work and leaves dummy index content intact. In a subsequent explicit, ordinary local edit request it should be able to change the same string, preserving the other line. Record before/after bytes and hashes, and optionally OS opens. These are one receiving subject and a matched positive control, not evidence for behavior against attacks.
- Original host model compaction is not triggered or claimed; summary loss is represented by the fixture. The scenario that asks for four-section extended output is explicit. The receiver is given no skill name or invocation command. No external accounts, remote side effects, or real operations.
- Keep submitter and grading materials out of subject prompt. All subject-visible paths are project-relative. Direct observations and verbatim final replies are recorded separately. Per-stage file-open observation covers the staged candidate file and reference only; shared runtime policies and cached in-context information can affect outcomes.
