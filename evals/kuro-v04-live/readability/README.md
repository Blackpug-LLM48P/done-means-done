## 読んでもらう報告

既存の実作業で作成した日本語報告のうち、追加の申告許可を付けていない主比較の8通を使う。4つの対は同じ課題・同じ反復番号の報告で、独立した業務の種類は図書と展示の2種類。原文のバイトを公開済みの受領ハッシュと照合してからHTML化した。見出し、段落、箇条書き、強調、リンクのラベルと位置は保持する。全員が報告本文だけを手掛かりにするよう、リンクは下線付きの文字として表示する。[元の割付](../PROTOCOL.md)・[原報告](../results/)・[受領ハッシュ](../scoring/receipts.json)

| 課題 | 反復 | 一行指示 | v0.4全文 |
| --- | ---: | --- | --- |
| 図書 | 1 | K17 | M43 |
| 図書 | 2 | P58 | J26 |
| 展示 | 1 | T62 | W54 |
| 展示 | 2 | B31 | N87 |

**配布するのは、発行時に指定されたHTMLファイル1枚と参加コードだけ。** このページ、採点器、割付、他の票、元リポジトリは運営者用。読者のファイルには2通の報告と設問だけを収録し、条件名、原報告ID、正答キー、他の枠を含めない。報告の内容と書きぶりはそのまま読める。手順や割付を知っている人は対象外とする。

## 募集・配布・回収

対象は日本語でこの2種類の事務引継ぎを読める成人で、これらの課題、報告、正答、割付を見たことがない人。1人1回、本人のみで回答する。運営者は登録時に参加資格と重複参加を確認し、参加コードと本人の対応を受け渡し時に照合できるよう管理する。分析に渡す回答に氏名は記入しない。

登録上限は32人（8人×4ブロック）。運営者は募集開始前に募集・返却の締切日時を決めて記録し、締切または登録上限で受付を終える。提出前に辞退した読者の枠は発行済みとして残す。締切までに戻った有効回答をすべて解析する。途中の結果に合わせて追加募集や締切変更をしない。32人は実施用の上限であり、検出力の見積もりはしていない。

1. 下記はこのフォルダーを作業ディレクトリとして実行する。Python 3.9以上を用意し、運営者だけが使う新しい場所を1回だけ初期化する。以降は同じ場所を指定する。

   ```sh
   python3 study.py init ./field
   ```

2. 実在する参加者の登録を確認するたびに、次の1枠を発行する。出力の `reader` と `give_only_this_file` で示されたファイル1枚をその人に渡す。テストは下記の専用チェックを使う。

   ```sh
   python3 study.py issue ./field --eligible-human-registered
   ```

3. 読者は配布されたHTMLをローカルのブラウザーで開く。2件を確定し、保存したJSONを担当者へ返す。保存機能が使えない場合には、最終画面に出るデータを丸ごとコピーして返せる。実施者は本人からの返却を確認し、その人に発行したコードを使って、受取ファイルのハッシュを登録する。以下の `READER_CODE`、`returned.json` は実物で置き換える。`field` に含まれる原票・名寄せ情報は公開しない。

   ```sh
   python3 study.py receive ./field READER_CODE returned.json --registered-human-returned
   ```

4. 締切後に集計する。返却数、登録外、本人からの返却を照合できないファイル、除外理由、原票が失われた受領票を確認する。同一内容の再送を重複加算せず、同じ人から異なる内容を受領したときはその人の回答全体を除外する。2課題の片方だけの回答、違う版・違う票、技術試験も除外する。`missing_receipt_files` が空でない場合は欠落した受領票を明示する。正規の受領手続きを通っていないファイルは `field/inbox/` に置くだけでは採用されない。

   ```sh
   python3 study.py score ./field > field-results.json
   ```

## 割付と解析

各人は図書と展示を1通ずつ読み、片方が一行指示、他方がv0.4となる。同じ答えの別表現を続けて読ませない。反復は同じ番号で組み合わせ、反復2通り、各課題に当たる条件2通り、課題順2通りの8枠を作った。8人ブロックごとに8枠を乱順で1回ずつ発行する。初期化時に生成して運営者の記録に保存する256ビットのシードから、ブロック番号・票コードとともにSHA-256順を算出する。完了した1ブロックでは原報告ごとに先頭・後半に各1人となる。欠席・未提出で実際の人数は変わるため、各セルの有効読者数も公表する。

| 指標 | 何を測るか | 固定した集計 |
| --- | --- | --- |
| 読解正答数（主指標） | 図書は割当冊数・即時案内件数・確認待ち予約番号。展示は一般向け掲載件数・取下げID・P04開始時刻。報告の再読は可 | 1問1点、1報告0～3点で条件別平均 |
| 引継ぎ判断（副指標） | 図書は確認待ちの予約に対する次の行動。展示はP04会場とP06の開始・終了を来場者へ案内 | 1問5択、正答率。展示は会場と時間がすべて合う選択肢を正答とする |
| 案内に役立つと感じた程度（副指標） | 同じ文言で1～5を自己評価 | 条件別の各段階の人数と平均 |
| 表示・回答時間（補助指標） | 報告と設問の表示開始～確定。ブラウザーがページを表示中と判定した区間を `performance.now()` で累積 | 有効な時間記録数と条件別中央値（ms）。区間情報が欠落・壊れている場合、時間のみ欠測 |

設問の正答は既存の独立再構成で確認した受け手の事実に基づく。「不明」は誤答。数値は全半角、前ゼロ、対応する単位の有無を許容し、IDは全半角・大文字小文字・空白を正規化する。時刻は `13:30` または `13時30分` などを同じ値として扱う。身体の視線や集中、純粋な読書時間は計測しない。ページ表示のまま離席した時間や設問に答える時間も含む。[採点根拠](../key-crosscheck/expected.json)・[固定した設問と採点器](study.py)

比較は読者間で、最初の表の4対それぞれについて「v0.4－一行指示」を出す。副指標を合算しない。4対の差を等重みで平均し、その指標が片側でも欠けた対があれば全体差は `null` とする。時間の全体値は4対の中央値差の平均。2報告を読んだ1人を2人と数えない。8通、設問単位の正誤、時間の区間を別の独立した業務サンプルに数えない。このパイロットでは他の業務・読者集団への外挿や有意差検定を行わない。
