# Single-checkpoint development pilot

Pre-output specification. The anonymous arm mapping is D = M0 (checkpoint verbatim in a fresh receiver, a proxy for continued conversation), Q = M1 (ordinary handoff), V = M2 (prompted evidence-guided reconstruction; no separate verifier or adoption loop). G supplies Q, H supplies V. Both maintainers see the same checkpoint plus their respective instructions, one call each, same inherited model/effort, same 900-byte UTF-8 cap. If a response exceeds the cap, keep bytes up to 900, dropping a trailing partial word. Save the full reply. Maintainers and receivers run in separate no-history workers, with no key or other arms presented. Use local scripting only to pass/score texts. All arms use the same downstream request and local harness.

A single snapshot includes one challenged batch (Sorrel, a valid revision update, repeated stale claim, and queued check), a clean positive control (Flint, a closed and stageable batch), and a clean negative control (Iris, an absent local input). The three batches and their fields are not independent trials. Serialized machine fields are primary; retain raw English reports for review. Field checks: revision correct; set of passed checks correct; seal state correct; original current-check receipt ID among supplied basis (allow extra IDs, ID presence only); number of independent complete receipts correct; selected action and revision yield the correct local artifact. Record unsupported seal-pass claims and failure to acknowledge pending status. Flag a pending batch if its seal_state is unknown or pass. A raw-language conflicting completion assertion is a separate manual observation. Do not sum scores into a stress or overall score or treat one draw per arm as an effect estimate.

Local harness reconstructs the same synthetic checkpoint for every arm with three independent pack files, two strips, and a revision-specific station receipt ledger. It gates stage on current revision and both passed checks, review queue on a pending check with input present, and input-request on a pending check with input absent. It snapshots artifacts, can be replayed in a temporary directory, never mutates the checkpoint. Counterfactual harness checks before data collection: staging Flint r4 succeeds; staging Iris r1, queueing Iris r1 and staging Sorrel r2 must be refused. A requested input signals missing material and does not restore it.

Boundaries: no iteration, no audit feedback or post-audit report, no repeated compaction or genuine in-place continuation, no separate novel-question turn, no source-loss arm, no incentive variation, no matched additional-inference-only condition, no wait control, no test of evidence verifier or weight/retrieval changes. Compare bytes and calls. Measured tokens, temperature, seed, per-worker costs and hidden model state may be unavailable. No adoption decision from this one checkpoint. No product invocation or modification.
