# 修正案の独立確認で誤提示を止められるか

**追加確認の採用、無人適用ともに保留した。** PR #12の既知40本で、確認役は有用な修正17本をすべて承認し、誤った3候補のうち1本を止めた。残る2本を提示したため、事前に定めた誤提示ゼロの条件には届かなかった。

R1単独では、R1が作った修正候補をそのまま提示する。追加確認ありでは、同じモデルの別セッションに原票、元文、同じ候補を渡す。R1の理由と作者票は渡さない。確認役が承認すれば候補を提示し、保留なら元文を保存して人手確認へ回す。R1が指摘しなかった本文は、両方式ともそのまま通す。DMD v0.4とB1の業務ドライランを固定した。[事前登録](PROTOCOL.md)・[確認役の実装](../../integrations/evidence_handoff/candidate_check.py)

| 対象 | 方式 | 正しい修正の提示／要修正 | 誤提示 | 正しい候補の誤保留 | 人手確認 | 正しく自動完結 |
|---|---|---:|---:|---:|---:|---:|
| 既知40本 | R1単独 | 17/18 | 3 | 0 | 0 | 37/40 |
| 既知40本 | 追加確認あり | 17/18 | 2 | 0 | 1 | 37/40 |

「正しく自動完結」は、正常な元文をそのまま通した場合と、必要な修正を正しく提示した場合を数える。誤った候補を保留しても、人手確認が残るためここには加えない。新作では、確認役に届いた6候補がすべて正しく、誤った候補を止められるかを測る機会は0件だった。新作単独では候補提示の採用条件を通過し、両集合で通過する条件は既知集合で未達となった。[各集合の成績と採否](results/summary.json)・[案件別の判断](results/events.json)
