# Public PR #8 transport adapter

`pr8-adapter.json` binds the replay to bytes from the pinned PR #8 commit. Each `source_row` refers to a **one-based** entry in the case's original `records` array. The driver copies the source text, request and draft verbatim. A single source document can support more than one distinct check. The two original target phrasings are kept in each historical replay record.

The registry is a manual interpretation for this experiment. References, check names, source classifications, result flags, synthetic year-2000 timestamps and revision, and the clean reference lists were added here. The adapter puts the revision on each individual B field. Times have no historical significance and do not reinterpret dates or times in the quoted source texts. Synthetic amendments for malformed messages exist in memory only. The PR #8 observations contain handoff prose and bare labels. Nothing in this replay measures historical production of evidence references.

M3V7 explicitly requests the receipt record in the report, along with the monthly genre counts. The signed receipt confirms the first report check and separately bears on actual handover. For M3V7 and S4K9, indirect notices of a missing annex and missing day-two ledger remain reported. The clean open-report witness cites direct partial data (receipt and first-day count, respectively). The cited data cover only the first check and the second has no eligible direct record. For Q8F2 and S4K9, the service-desk inquiry and committee minutes directly record a deferred decision.

`design/receiver-controls.md` and its pre-trial addendum `design/receiver-controls-revision.md` define the expected action vectors independently. `method/controls.py` replays the four combination cases and the separately identified AG5 development-case output. The latter exercises A with the historical `state` and `handoff` unchanged and requires no evidence-registry adapter. No historical responses are regenerated.
