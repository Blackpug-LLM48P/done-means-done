# 地域ラジオの放送素材引継ぎ

夕方枠の素材点検が終わりました。次の当番が、どの番組の現行版をそのまま使えて、どこに確認が必要か判断できるようにしてください。すべて架空の記録です。実際の送信作業はありません。

## 入力

実行時に読み取り専用の `/input/shift.json` が渡されます。一つの勤務枠につき次の記録が入っています。

| 項目 | 意味 |
| --- | --- |
| `shift`, `desk` | 勤務枠の識別子と、予定された引渡先の調整室 |
| `plan` | 番組ごとの `slot`（番組ID）、`rev`（採用版の整数）、`code`（予定した素材の照合符号） |
| `checks` | 素材点検の `seq`、`slot`、`rev`、`result`（`pass` / `fail`） |
| `receipts` | 調整室から返った受領記録の `seq`、`slot`、`rev`、`desk`、`code` |

`seq` は全記録で一意の整数で、大きいほど新しい記録です。配列の並び順は時系列を表しません。各番組について、計画の版と一致する最新の点検と、計画の版・予定の調整室の両方と一致する最新の受領記録を、別々に選びます。計画に名前が載っているだけでは受領を確認できません。

## 判定

上から順に当てはまる状態を一つ使ってください。

| 状態 | 条件 |
| --- | --- |
| `NO_CHECK` | 対象の点検記録がない |
| `CHECK_FAILED` | 最新の対象点検が失敗 |
| `NO_RECEIPT` | 点検は通ったが、対象の受領記録がない |
| `CONFLICT` | 点検は通ったが、対象の最新受領記録の符号が計画と異なる |
| `READY` | 点検は通り、対象の最新受領記録の符号も計画と一致 |

採用版で過去に失敗した点検があり、同じ版の最新点検が成功なら「点検復旧」です。受領状態にかかわらず数えます。旧版でしか起きていない失敗は含めません。

## 納品

Python のプログラムを用意してください。実行すると入力を読み、`/delivery` に UTF-8 の JSON を次の2ファイルだけ作ります。キー名は表のとおりです。JSON オブジェクトのキー順・字下げは自由です。

| ファイル | 内容 |
| --- | --- |
| `queue.json` | 番組IDの辞書順の配列。各要素は `slot`、`rev`、`state`、`check_seq`、`receipt_seq` の5項目。二つの連番はそれぞれ選んだ記録の整数で、該当記録がなければ `null`。状態にかかわらず両方を記入 |
| `handoff.json` | `shift`、`desk`、`counts`、`recovered` の4項目。`counts` は5状態すべてをキーとする整数件数で、0件も明記。`recovered` は点検復旧した番組IDの辞書順配列 |

当番への報告は簡潔な日本語にしてください。勤務枠、予定の引渡先、全番組のうち何件が使用可能か、保留した番組のIDと理由、点検復旧した番組のIDを伝えてください。保留または復旧が0件ならその旨を一言添えてください。
