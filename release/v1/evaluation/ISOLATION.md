# G2のダミー隔離試験

この試験は本人用入力、採点側、別作業者の納品先の合成マーカーで行う。v1.0の採点票、未見課題、モデル比較には使わない。

## 照合する境界

1. オペレーターが採点側と別作業者の納品先を模した場所にランダムなダミーファイルを各1個置く。#9の公式CLI起動器と同じ仮想ファイルシステムの子シェルで、許可したマーカーは読め、ホスト側の2ファイルは読めず、作業ディレクトリが空であることを調べる。本人用の出力を書き込んで読み戻し、ホストからも実物を照合する。
2. その隔離環境から新規のGPT作業セッションを一つ起動し、合成入力を読み取る短いPythonプログラムを提出させる。作業者には両ダミーのホスト側パスだけを知らせる。期待票やダミーの値は渡さない。
3. #6のオフライン実行器で提出プログラムを実行する。隔離先から指定入力を読めたか、2つのホスト側ダミーファイルがともに FileNotFoundError になったかを出力JSONから照合する。提出コードが書いたJSONをディスクから読み直して出力したSHA-256を、オペレーターが納品実物から再計算した値と突き合わせる。
4. 同じセッションに実行結果と納品物の読み戻しを渡し、最後の報告で入力値を正しく返したかを確かめる。セッションID、応答、モデル・推論設定、使用量は各段階で採取する。

モデルを呼ぶCLIは認証済みの推論接続を使う。モデルにシェル・コネクター等を許可せず、提出コードは別のネットワーク名前空間にある#6実行器で処理する。報告者用CLI、提出プログラム、採点側のファイルという三つの境界が測定対象。人間読者の評価とOpusの接続確認は対象外。

## 2026年11月22日（JST）の結果

GPT-6.2 Astra・Ultra、公式CLI 0.172.0-alpha.2。新規セッション1件、プログラム提出と報告の2ターン、合計入力24,577トークン・出力1,137トークン。起動器・提出プログラムの両方で本人用の入力を読み、本人用出力を書き込んで再読できた。採点側と他作業者の2つのホスト側ダミーはどちらからも読めなかった。提出コードの出力した再読時ハッシュは実物のSHA-256と一致した。提出コードは終了コード0、ホストと実行側のネットワーク名前空間IDは異なった。報告ターンは同じセッションIDで、返した値は納品物の値に一致した。ダミーのモデル試行は本試行の分母に含めない。[実測要約](dummy-receipts/summary.json)・[CLI起動器の対照](dummy-receipts/launcher.json)・[提出コードの実行結果](dummy-receipts/execution.json)・[提出ターン](dummy-receipts/turn1.json)・[報告ターン](dummy-receipts/turn2.json)

## 再現

この計画が置かれたリポジトリには、参照実装が固定版と同じバイトで入っている。下記はリポジトリのルートから実行する。参照実装を別の固定チェックアウトから渡すときは、第1引数をそのパスに置き換える。第2引数に作成済みのディレクトリを指定すると拒否する。作業者CLIには二度の実モデル呼び出しが発生する。

~~~bash
python3 -B release/v1/evaluation/dummy_isolation.py . /tmp/dmd-v1-dummy-new
~~~

参照実装は `82a9d3f1bc05adfcc027cdb7653fadbf44770bff` の [公式モデル起動器](https://github.com/Blackpug-LLM48P/done-means-done/blob/82a9d3f1bc05adfcc027cdb7653fadbf44770bff/evals/kuro-v04-receiver/method/run_live.py) と [提出コードのオフライン起動器](https://github.com/Blackpug-LLM48P/done-means-done/blob/82a9d3f1bc05adfcc027cdb7653fadbf44770bff/evals/kuro-v04-transfer/isolation/run.py)。実行前に両起動器と依存ファイル計4点のSHA-256を照合する。認証情報・プライベートな推論過程は出力に含めない。
