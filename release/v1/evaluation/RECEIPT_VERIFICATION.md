# G3　GPT枠の受領照合

実行が停止し、レシートの書込みが終わった時点で次を実行する。照合用のコードは正解票・採点票・他系列の割付を参照しない。

```sh
python3 release/v1/evaluation/verify_wave.py private-run/study private-run/gpt-receipts
```

標準出力はJSON。引数1は運営用の `commitments.json` と `assignments/gpt.json` を持つディレクトリ、引数2は `registration.json` と匿名の各枠の記録を持つディレクトリ。ルートの `C01.log`〜`C08.log` は進行表示用としてそのまま残せる。提出数・使用量は各枠の原記録から集計する。既定ではスクリプトと同じ場所にある公開登録の `assignment-digests.json` と `commitments.json` を使う。監査時は事前登録commitから読み出したディレクトリを `--public` に渡せる。

- 公開登録と非公開の割付・入力コミットメントのハッシュを照合し、8入力それぞれにB・Cの独立した匿名枠が1つずつ存在することを確認する。
- 提出済み枠では、登録と指示のハッシュ、2ターンのプロンプト・セッション・応答件数、実行記録中の入力・プログラム、ディスク上の納品バイト、原報告のハッシュを照合する。各ターンのトークンはCLIの累積値の差とrolloutの最終ターン値に一致するかを検査する。原文の正誤は判定しない。
- 枠別の出力には匿名実行ID、状態、観測できたターン数・使用量、CLI時間合計、終了済みなら枠の経過時間を含む。納品ファイルの件数とハッシュ表のダイジェスト、原報告SHA-256を出力する。枠の `receipt_manifest_sha256` は枠ルートからの相対パスをキー、バイト数とSHA-256を値とした全ファイルの辞書のダイジェスト。JSONはUTF-8、キー順、インデント2、末尾LFで固定する。公開JSONにケース番号、条件名、原文、セッションIDは含まれない。
- 提出のない枠はレシートの状態に応じて `unstarted`、`started`、`interrupted`、`missing` として集計する。未保存ターンの消費は不明。明示的に残った使用量だけを合計し、キャッシュ分と推論分は内数として扱う。実行終了コードや提出済み状態は、納品物の正解を意味しない。
- 整合性に問題があれば非ゼロで終了する。有効な途中記録は終了コード0でも `all_submitted` がfalseになる。全16枠がsubmittedかつ整合する場合のみtrueになる。GPT波の完走だけでG3全体の完了を宣言しない。
