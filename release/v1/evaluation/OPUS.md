# Opus系列の16枠を引き継ぐ

対象は[事前登録した8案件](PROTOCOL.md)のOpus波。GPT先行波と同じ業務入力・一行指示・DMD本文を使う。実行の単位は1案件・1条件・新規の作業者1人。この実行環境では正規のOpusホストへの接続を確認できていない。以下は別ホストでの実行手順で、Opusの試験成績は含まない。

## 引き渡す人の操作

1. 運営者が事前登録のcommitと、実際に固定した8入力・割付表のハッシュを引き継ぐ。採点票を閉じたまま、私有の割付表でOpus系列の対象枠を選ぶ。奇数案件はC・B、偶数案件はB・Cの順。各枠に不透明な実行IDを使う。
2. 固定した入力のうち、当該案件の5ファイルだけを取り出す。名称は `request.txt`、`scope.json`、`items.csv`、`parts.csv`、`events.csv`。各ファイルから入力ダイジェストを再計算し、当該枠の事前コミットメントと合わせる。条件文は一行条件の固定文字列またはSHA-256照合済みの本体。条件名や割付表をプロンプトに書き足さない。
3. Opusホストとオフライン実行ホストは別のマシンでもよい。Opusホストに渡す作業者入力は第1ターンの依頼文と第2ターンの読み戻しだけ。オフライン実行担当が当該5ファイルと提出されたプログラムを受領する。正解票、乱数種、全案件の対応表、他の報告、個人の作業履歴は運営側に保管する。

## 接続とダミー確認

正規ホストのモデル識別子、クライアント名・版、推論設定とツール設定を、実行前に非機密の記録として残す。ホストが実際に返すモデル名でOpus系列を確認する。既存のGPT向けダミーの成績をOpusの隔離確認に転記しない。

実作業と同じ権限で新規ダミーセッションを始める。作業者は指定した入力を扱え、提出コードは許可したファイルを作成・読戻しでき、採点側に置いた合成マーカーと他者のダミー成果物を参照できないことを確認する。モデルの利用可能なツール、提出コードのプロセス、両ターンが同じ作業者セッションになっていることを個別に記録する。実測したモデル・ホスト・権限は系列内で固定する。

## 1枠の運転

| 順序 | 担当、入力、保存物 |
| --- | --- |
| 1 | 運営者が共通の第1プロンプトを作成。Opusの新規セッションへ一度渡し、実際に送信したUTF-8バイト、セッションID、開始時刻、ホストが返した応答原文を保存する |
| 2 | モデルが返したプログラムを共通の抽出器に通す。オフライン実行器に当該案件の5ファイルとプログラムを渡し、終了状態、出力と納品バイトを受領する。誤りや未納もそのまま記録する |
| 3 | 運営者が共通の第2プロンプトに実行結果と納品物の実際の読み戻しを組み込み、同じOpusセッションに送る。応答をそのまま最終報告に保存する |
| 4 | 実行ID、配布内容SHA-256、ホストとモデル、同一セッションの両ターンの参照、状態・時刻、取得可能な使用量、両プロンプト、プログラム、実行受領書、納品バイト、最終報告の対応を固定する |

受領側は送出時のハッシュへ戻して各ファイルを照合し、未着・途中中断・納品内容の不合格を別の状態に記録する。アカウント情報や内部推論は記録に加えない。料金・使用量を取得できなければ未取得と記録する。実作業開始前の障害と入力受領後の欠測は事前登録の再起動規則に従う。採点側の開封は全32枠の提出・終了状態を確定した後。[別ホスト受領の既存設計](../../../evals/kuro-v04-live/crossfamily/README.md)

## 共通プロンプトを出力する

運営端末で `opus_packet.py` を使う。前提は固定リポジトリのチェックアウト、`staging/packets/`、`staging/commitments.json`、Opus専用の割付ファイル。事前登録のSHA-256を照合して、GPTと同じ関数でプロンプトを作る。下の例は奇数案件の最初の枠。変数には運営が管理する実際のパスと固定ハッシュを指定する。

~~~bash
python3 -B release/v1/evaluation/opus_packet.py prepare "$repo" "$staging" "$opus_jobs" "$jobs_sha" "$commitments_sha" C01 C "$runs"
~~~

表示された `prompt1.txt` だけを新規のOpusセッションに渡す。返答の原文を同じ枠の `raw-program.txt` に保存し、オフライン実行器を使用できるLinux上で次を実行する。

~~~bash
python3 -B release/v1/evaluation/opus_packet.py followup "$repo" "$staging" "$opus_jobs" "$jobs_sha" "$commitments_sha" C01 C "$runs"
~~~

表示された `prompt2.txt` を同じOpusセッションに送り、原文を同じ枠の `REPORT.md` に保存する。両ターンのホスト発行レシートを `turn1.json`・`turn2.json` に保存し、枠の状態、実時刻、配布ハッシュ、最終報告のハッシュを `status.json` に記録する。手順にある `prepare` だけを実行してもモデル試行数は増えない。入力受領後の例外では、同じ枠の提出コードを再実行せず、その時点までの記録を保存する。
